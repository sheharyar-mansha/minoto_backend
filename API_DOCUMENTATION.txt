================================================================================
MINOTO BACKEND — HTTP API REFERENCE (FastAPI)
================================================================================
Base URL (local):   http://127.0.0.1:8000
API prefix:         /api/v1   (set API_V1_PREFIX in .env)
Interactive docs:   GET  /docs   (Swagger UI)
OpenAPI JSON:       GET  /openapi.json

Static uploads:     GET  /media/<relative_path>
                    Example: avatar_url or voice_file_path returned as "avatars/{userId}/..."
                    Full URL: {BASE}/media/avatars/...

--------------------------------------------------------------------------------
AUTHENTICATION
--------------------------------------------------------------------------------
Except where noted, endpoints require a JWT access token:

  Authorization: Bearer <access_token>

Obtain tokens via POST /auth/register or POST /auth/login (see below).

Token payload: subject (sub) = user UUID string.
Default expiry: 7 days (ACCESS_TOKEN_EXPIRE_MINUTES in .env).

AUTH  (prefix /api/v1/auth)
--------------------------------------------------------------------------------
POST   /api/v1/auth/register
       Body JSON:
         { "full_name": string, "email": string, "password": string (min 8) }
       Response 201:
         { "access_token": string, "token_type": "bearer", "user": UserOut }
       Errors: 409 if email exists

POST   /api/v1/auth/login
       Body JSON:
         { "email": string, "password": string }
       Response 200: same shape as register success
       Errors: 401 invalid credentials

UserOut shape:
  id, email, full_name, default_export_format, include_timestamps_default,
  avatar_url? (relative path under /media, e.g. user_avatars/...),
  created_at, updated_at  (ISO 8601 datetimes)

--------------------------------------------------------------------------------
CURRENT USER & PREFERENCES  (prefix /api/v1/users)
--------------------------------------------------------------------------------
GET    /api/v1/users/me
       Response: UserOut (same fields as above)

PATCH  /api/v1/users/me
       Body JSON (all optional):
         { "full_name"?, "default_export_format"?, "include_timestamps_default"? }
       Response: UserOut

POST   /api/v1/users/me/avatar
       Content-Type: multipart/form-data
       Field: file (image)
       Response: UserOut (avatar_url set; previous user_avatars/... file removed if any)

--------------------------------------------------------------------------------
MEMBER DIRECTORY  (prefix /api/v1/members)
--------------------------------------------------------------------------------
All routes scoped to the authenticated user (your org directory).

GET    /api/v1/members
       Query:
         skip   (default 0, >=0)
         limit  (default 50, 1..100)
         q      (optional) search substring in name or email (case-insensitive)
         saved_to_directory (optional bool) filter directory vs meeting-only members
       Response: PaginatedResponse<MemberOut>
         { "items": [...], "meta": { "total", "skip", "limit" } }

POST   /api/v1/members
       Body JSON:
         name, email, role?, member_since? (YYYY-MM-DD), saved_to_directory (default true)
       Response 201: MemberOut

GET    /api/v1/members/{member_id}
       Response: MemberOut
       Errors: 404

PATCH  /api/v1/members/{member_id}
       Body JSON (partial): name?, email?, role?, member_since?, saved_to_directory?,
         avatar_url?, has_voice_sample?, voice_duration_seconds?
       Response: MemberOut
       Note: prefer POST .../avatar for binary avatar uploads.

DELETE /api/v1/members/{member_id}
       Response: 204 (removes voice file on disk if stored under uploads/)

POST   /api/v1/members/{member_id}/voice
       Content-Type: multipart/form-data
       Field: file (binary)
       Query: duration_seconds? (optional int, for UI display)
       Replaces previous voice file if any.
       Response: MemberOut (has_voice_sample=true, voice_file_path relative to /media)

POST   /api/v1/members/{member_id}/avatar
       Content-Type: multipart/form-data
       Field: file (image)
       Response: MemberOut (avatar_url set to relative path under /media)

MemberOut:
  id, name, email, role?, member_since?, saved_to_directory,
  avatar_url?, has_voice_sample, voice_duration_seconds?,
  created_at, updated_at

--------------------------------------------------------------------------------
MEETINGS  (prefix /api/v1/meetings)
--------------------------------------------------------------------------------
GET    /api/v1/meetings
       Query:
         skip, limit (same as members)
         scope: "all" | "upcoming" | "conducted"
           - upcoming: status in draft|scheduled|in_progress AND meeting_date >= today
           - conducted: status == completed
         q: optional title substring (ilike)
       Response: PaginatedResponse<MeetingListItemOut>
         MeetingListItemOut:
           id, title, date_label, duration_label, meeting_date, duration_minutes, status
       Visibility:
         - admin/host users: meetings they own (created)
         - member users: meetings where their login email matches a participant member email

POST   /api/v1/meetings
       Body JSON:
         title, meeting_date (YYYY-MM-DD), start_time ("HH:MM" 24h),
         duration_minutes (int), status (default "scheduled")
         status enum: draft | scheduled | in_progress | completed | cancelled
       Response 201: MeetingDetailOut

GET    /api/v1/meetings/{meeting_id}
       Response: MeetingDetailOut
         id, title, date_display, start_time, duration_display,
         meeting_date, duration_minutes, status,
         existing_members_count, new_members_count,
         participant_avatar_urls (length 3: first roster slots, relative paths or null),
         existing_preview_avatar_urls (length min(3, existing_members_count): random existing
           members' avatar_url or null; for UI preview of "existing" card),
         participant_member_ids (ordered roster member UUIDs)
       Visibility:
         - owner can always read
         - member users can read if their login email is in the meeting participant roster
       Counts derive from roster:
         is_new_for_meeting true  -> new_members_count
         is_new_for_meeting false -> existing_members_count

PATCH  /api/v1/meetings/{meeting_id}
       Body JSON (partial): title?, meeting_date?, start_time?, duration_minutes?, status?
       Response: MeetingDetailOut

DELETE /api/v1/meetings/{meeting_id}
       Response: 204

PUT    /api/v1/meetings/{meeting_id}/participants
       Body JSON:
         { "member_ids": [ "<uuid>", ... ] }   (deduplicated server-side; order preserved)
       Replaces entire roster. For each member:
         is_new_for_meeting = NOT member.has_voice_sample
           (needs voice enrollment for this org; independent of saved_to_directory)
       Response: MeetingDetailOut
       Errors: 400 if any id is not owned by the user

POST   /api/v1/meetings/{meeting_id}/complete
       Sets status=completed, conducted_at=now
       If an active live session exists for this meeting, server computes final elapsed
       (including currently running segment), computes overtime, and clears that
       active session row for this user.
       Response:
         {
           "id", "status", "conducted_at",
           "final_elapsed_seconds"?, "target_seconds"?, "overtime_seconds"?
         }

POST   /api/v1/meetings/{meeting_id}/recordings
       Content-Type: multipart/form-data
       Field: file (audio chunk/full recording from one device)
       Query:
         duration_seconds? (optional int)
         device_label? (optional string, max 128)
       Access:
         - owner (admin/host): allowed
         - member user assigned to the meeting by email: allowed
       Response 201: MeetingDeviceRecordingOut
         {
           "id", "meeting_id", "uploader_user_id", "participant_member_id",
           "device_label", "media_path", "mime_type",
           "duration_seconds", "byte_size", "created_at"
         }

GET    /api/v1/meetings/{meeting_id}/recordings
       Lists uploaded device recordings for this meeting.
       Access:
         - owner: sees all meeting recordings
         - assigned member: sees only recordings uploaded by that member user
       Response 200: MeetingDeviceRecordingOut[]

--------------------------------------------------------------------------------
LIVE RECORDING SESSION (mobile timer sync)  (prefix /api/v1/sessions)
--------------------------------------------------------------------------------
GET    /api/v1/sessions/active
       Response 200: LiveSessionOut or JSON null if none
         meeting_id, title, elapsed_seconds, is_paused,
         running_since_ms (nullable), total_target_seconds

PUT    /api/v1/sessions/active
       Body JSON (replace or create):
         meeting_id, title, elapsed_seconds, is_paused,
         running_since_ms?, total_target_seconds
       Validation:
         - is_paused=true  => running_since_ms must be null
         - is_paused=false => running_since_ms is required
       Response: LiveSessionOut
       Errors: 404 if meeting_id not found / not owned

DELETE /api/v1/sessions/active
       Clears server-side active session for this user
       Response: 204

STATS  (prefix /api/v1/stats)
--------------------------------------------------------------------------------
GET    /api/v1/stats/summary
       Response:
         { "meetings_this_week": int,  // completed, conducted_at in current ISO week
           "total_recorded": int }     // all completed meetings for user

--------------------------------------------------------------------------------
DATABASE & MIGRATIONS
--------------------------------------------------------------------------------
- Configure DATABASE_URL in .env (SQLite default: sqlite:///./minoto.db).
- From backend folder:
    alembic upgrade head
- Tables: users, members, meetings, meeting_members, meeting_live_sessions,
  meeting_device_recordings

--------------------------------------------------------------------------------
RUNNING LOCALLY
--------------------------------------------------------------------------------
  cd backend
  python -m venv .venv
  .venv\Scripts\activate          (Windows)
  pip install -r requirements.txt
  copy .env.example .env          (set DATABASE_URL if not using SQLite)
  alembic upgrade head
  uvicorn main:app --reload --host 0.0.0.0 --port 8000

Mobile .env: API_BASE_URL=http://10.0.2.2:8000/api/v1  (Android emulator to host)

--------------------------------------------------------------------------------
CONVENTIONS FOR FRONTEND TEAM
--------------------------------------------------------------------------------
- All UUIDs are string UUID v4 (36 chars).
- Dates: ISO date "YYYY-MM-DD"; list/detail include human labels where noted.
- Errors: JSON { "detail": string | array } (FastAPI default).
- Pagination: always skip/limit + meta.total for list endpoints.
- File fields from this API are stored as paths relative to upload root; prefix with
  /media/ on the same host as the API for GET (no auth on /media in dev — lock down in prod).
